# 迁移计划：mac 保真栈并入 upstream-mac（收尾 + CoreText 整形决策与移植）

## Context

上游 v0.3.0 已成为唯一维护线（官方三平台 wheel），我们须把 mac 保真能力以最小分叉方式并入上游架构。前一段迁移（信号修复/追踪器/案例/测试）已完成 4 个提交并验证（smoke 10/10、17 项测试 17/17）。本计划覆盖剩余两件事：

1. **M0 收尾**：network_smoke 的 H2 stream timeout 定位 + PR 材料。
2. **M1–M3 字体整形迁移**：上游 mac 用 HarfBuzz 整形（Windows 同构），我们 merge-macos-port 线用 CoreText 原生整形并已实证与真 Firefox mac 逐字符 0 差异（letter-spacing 4/4）。上游 HarfBuzz-mac 与真 FF 的差距未实测——先实证，再决定是否移植。

**今日调研的关键事实**（已实证，改变原 4–6 周评估）：
- 字体域语义分叉合计 ~140 行，集中在 `src/web_geometry/`（161 "冲突" 主要是行尾噪音，如 font_collection.cpp 字节差一倍、语义 0 差异）。
- 上游容器已就绪：`font_backend.h` 非 Windows 分支 = CoreText 底层 + DirectWrite 形状 API 模拟（`IDWriteFontFace` 持 CTFontRef、`CoreFont()` 访问器）；`font_face_mac.cpp` 是 shim 实现；CoreText 枚举与 port 线语义零差异。
- **port 线没有 Darwin ShapeFont**：CoreText 路径绕开 FontRun（`font_coretext.cpp:116 MacTextLine` → `glyph_coretext.cpp` 的 CanvasGlyphRuns/BuildCanvasTextPath/BuildCanvasGlyphMasks 直出 canvas 数据；`metrics_coretext.cpp` 提供 Measure/MeasureCanvas/LineMetrics/SvgLengthMetrics）。
- **构建零改动**：darwin 上 `src/web_geometry/*.cpp` 由 `tools/product_sources.py:127` 的 glob 自动编入，port 独有文件自带 `#ifdef __APPLE__`（Linux 上为空 TU）。移植障碍是符号冲突：upstream mac 已有 7 处 ShapeFont 版同名实现（canvas_text.cpp:29、system_font.cpp:113/:143、svg_length_font.cpp:5、canvas_text_path.cpp:87-152、glyph_runs.cpp:35/:197、glyph_mask.cpp），以及 `CanvasGlyphRun.face` 类型二选一（port=CTFontRef vs upstream=IDWriteFontFace*）。
- FontRun 死字段：`raw_advances/raw_offsets_*/glyph_clusters` 无消费者；必须填准的字段：glyphs、glyph_advances、glyph_offsets_x/y、advance、advances[]、clusters[]、ascent/descent（app units）、ink、box/unrounded。

## M2 — CoreText 整形移植（条件触发，3–5 天）

原则：保持 upstream 容器（IDWriteFontFace shim、FontRun、FontCollection），不翻转 face 类型，移植以 mac 分支形式接入（不搬整文件无关部分）。

1. **带入 port 独有文件**（自带 `#ifdef __APPLE__`，构建自动编入）：`mac_font_internal.h`（仅 MacRef/MacFontSize/MacFontInputValid 工具，丢弃与 font_backend.h 冲突的 mac 版 FontCollection）、`font_coretext.cpp`（MacTextLine/cascade/letterSpacing 关连字）、`metrics_coretext.cpp`、`glyph_coretext.cpp`、`glyph_mask_coretext.cpp`。
2. **face 类型统一走 `CoreFont()`**：glyph_coretext.cpp 内部改为从 `SelectedFont.face->CoreFont()` 取 CTFontRef（保持 upstream 的 `CanvasGlyphRun.face = IDWriteFontFace*`，避免牵连 context2d_paint.cpp、context2d_text.cpp:99-103、skia_target.cpp:1285、glyph_mask.cpp 等消费点）。
3. **符号让位**（mac 分支下）：upstream 的 7 处 ShapeFont 版实现改为 `#ifdef _WIN32`/Darwin 走 CoreText 版（canvas_text.cpp、system_font.cpp、svg_length_font.cpp、canvas_text_path.cpp、glyph_runs.cpp、glyph_mask.cpp 的 mac 段）；`font_shaping.cpp` 保留 HarfBuzz 作为 Windows 路径，Darwin 分支仅保留仍被消费的入口（如 CanvasFontBaselines 若无 CoreText 等价物则按 port 的 fallback 公式补）。
4. **适配层**：port 产出与 upstream 消费字段对齐（第 6 节清单）；ink 语义差异（CTLineGetBounds glyph-path 界 vs DWRITE metrics 推导）在 MeasureCanvas 返回的 CanvasTextMetrics 字段上一一对齐。
5. 构建脚本零改动；验证 `tools/product_sources.py` 的 LINUX_ONLY/NOT_LINUX 集合不受影响。
